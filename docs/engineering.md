# 工程治理

评估基准：v1.3.1。目标是同一产品范围内减少数据风险、修改影响和交互成本；保留离线无账号、六主题、自由记录及04:00打卡日。

## 判断与实施

| 发现 | 决定 | 验收依据 |
|---|---|---|
| 读取异常后默认数据进入自动保存，可能覆盖原件 | 加载失败阻止编辑和保存，独立恢复流程 | 损坏文件、读取重试、原字节保留 |
| 整文件直接覆盖，界面成功先于实际保存 | 两槽轮换与回读校验；可等待的保存队列；失败可重试 | 截断写入、磁盘写失败、连续修改、重启 |
| 一个Provider含全部业务与操作，所有控件订阅它 | 平台接入、Store、领域命令、领域reducer分离；选择器订阅 | 类型检查、选择器引用稳定、命令与存储集成测试 |
| 编辑器和列表在同一大页面，保存语义分散 | 独立MemoEditor，保持自动保存/保存/放弃，显示真实状态 | IME下首末行、选字编辑、回滚、后台草稿和写失败 |
| 今日与待办各自处理拖拽改期，移动/排序分多次dispatch | 一个共享确认流程，一个复合命令；隐藏条目参与一致的排名计算 | 跨组、重复/失效ID、已完成任务、筛选后的排序 |
| ScrollView把长组完整挂载，折叠不减少已挂载内容 | 日常浏览与多选平铺虚拟化；备忘录搜索固定在上方 | 千条数据、实际原生View数量、多选和末条搜索 |
| 静态检查不覆盖Android编译；死代码易累积 | noUnused门禁、导入边界检查、统一npm test、Android构建CI及手动UI工作流 | 本地构建/测试与独立CI结果分别记录 |

不以文件变短、测试数量或包数量作为质量结论。每个变化都要对应具体失败场景、维护边界或使用成本。

## 为什么没有全面重写或集中换依赖

- 保留 React Native/Expo：没有证据表明更换框架能以更低成本解决当前问题。只做Android时Kotlin/Compose也是合理方案，但重写还要重做数据迁移、键盘、主题及升级兼容。
- 暂不迁移 SQLite：当前首先需要的是保存确认、失败保护和恢复协议。用可替换Repository隔开界面与文件实现，后续可以独立迁移；对外JSON不是数据库文件。
- 暂不换整套UI库：六主题与紧凑布局已形成约定。引入Paper仍需逐项验证字号、密度、无障碍、原生模态和当前RN版本，不能把默认Material外观当作设计验收。
- 复用已有Gesture Handler处理拖拽生命周期：真实操作发现原PanResponder在预览重绘后会残留动画，且拖动使用可视分组索引操作交错的存储顺序，导致组内换位没有正确提交，因此保持原生手势实例稳定，并在松手时停止预览动画、按显示顺序规范化拖拽模型与限制滚动边界。保留跨组/日期布局规则，多选独立虚拟化，不引入另一套未经验证的完整拖拽库。
- 不fork完整任务软件：主流项目并不直接提供Lime的整套本地习惯/任务/备忘录语义，跨技术栈和许可证拼接会增加维护面。

可比较的基础库：[Expo SQLite](https://docs.expo.dev/versions/v55.0.0/sdk/sqlite/)、[React Native Paper](https://github.com/callstack/react-native-paper)、[Draggable FlatList](https://github.com/computerjazz/react-native-draggable-flatlist)。选型前核对当前锁文件的兼容性、维护状态、许可证和真实操作，不能仅按星数决定。

## 持续开发方式

1. 先写清触发场景、预期行为、数据边界与验收证据；反馈不是某个UI或架构实现的强制处方。
2. 先读现有规则与唯一任务卡，从最新main建聚焦分支。一次解决明确问题，保持每步可用。
3. 规则进入领域工具或reducer；平台I/O进入storage/native；共享操作进入hook，避免页面各自复制业务决策。
4. 改动只运行相关验证；发布再跑完整检查和正式包核验。Android编译、设备操作、存储回读各自记录，不互相代替。
5. 发布后更新真实文档。中间失败保留在私有任务证据中，不能从一次最终通过推导所有设备都兼容。

当前静态门禁检查纯业务层不依赖React/Expo或组件、页面不直接访问文件系统。它不能验证所有设计问题，仍需审查操作一致性和失败处理。

## 何时重新评估

- 数据规模测试显示保存延迟/内存或读取成本超出实际使用可接受范围时，独立评估SQLite与迁移回退。不能只靠增加防抖延迟掩盖问题。
- 排序模式在真实长列表或设备上持续出现手势/性能问题时，对候选拖拽库建立相同场景对照，再决定替换。
- 当前模拟器覆盖Android36，不等于小米15/澎湃OS3真机验收。收到真机反馈时优先复现，不用类型检查或XML全文证明触摸可用。
- 尚无同步、多设备或后台提醒需求；这些能力会改变数据/权限/生命周期设计，单独立项，避免顺带加入。
