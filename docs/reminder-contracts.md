# P4-A 本地提醒契约

日期：2026-10-09。实现前冻结；验收结果另记，不以本文作为送达证据。

## 范围

复用 Expo SDK55 的 `expo-notifications`，不使用 FCM、Expo Push Service、产品服务器或后台模型。设置中的一个紧凑入口管理通知许可、待办到期提醒和独立提醒。普通页面不插入 AI 面板。

独立规则支持单次、公历每年（生日可提前若干天及当天）。时间明确为 Asia/Shanghai，首版不支持农历；2月29日只在闰年发生，不静默改到其它日期。待办提醒须手动启用，已有日期但无时间的任务按上海时间09:00提醒；无日期、完成或回收站任务不排通知。普通待办编辑和 Agent 写入均通过数据库订阅触发重新核对。

## 数据与命令

新增 local-only `local_reminder_rules` 和 `local_reminder_instances`，不改旧记录ID/表类型。规则保存标题、备注、模式、单次日期或月日、时间、提前天数、当天开关、启用状态和 revision。实例保存规则/任务来源、来源版本、计划时刻、系统通知ID和状态，不把原始日记当提醒数据库。

`reminder.create/update/cancel` 进入现有 domain 校验、版本、事务和幂等回执。助手可查规则并生成可编辑建议，第一批不授予自动提醒写入；确认保存只是规则落库，通知许可和系统排程结果另行显示。助手不能把业务回执说成“已送达”。取消为软停用，可编辑规则后重新启用。

## 排程与恢复

开应用、回前台、规则/任务/开关变化时串行重算，先撤旧再排新。确定性系统ID含来源及版本/时刻的摘要；读取系统实际队列以修复“系统已排程、DB回执未写入”的中断。只操作 Lime 提醒前缀，不清除其它通知。侧效应不放SQL事务内，失败保留规则并给出可重试状态。

未来400天滚动窗口，最多预排128条，较远或超量项待下次打开重新核对，状态页明确限制。不在过去时刻立即补发；已过时间的实例标记“时间已过”，不等价于送达。修改、完成/删除任务、关闭开关、撤销通知许可均撤旧。年度长期提醒需要偶尔打开应用刷新窗口。

不自动弹权限请求：用户点开启时创建通知渠道再请求 Android 通知权限。不索取精确闹钟特殊权限；Android可能延迟，HyperOS锁屏/重启实际行为待真机验收。点击通知打开待办或提醒设置；冷启动延迟到导航就绪，不执行AI操作。第一批基础JSON备份未包含新规则，完整导出恢复在P5。

依据：[Expo SDK55 Notifications](https://docs.expo.dev/versions/v55.0.0/sdk/notifications/)、[Android通知权限](https://developer.android.com/develop/ui/views/notifications/notification-permission)、[Expo Android接收器清单](https://github.com/expo/expo/blob/sdk-55/packages/expo-notifications/android/src/main/AndroidManifest.xml)。Expo依赖为MIT许可，版本固定55.0.27；使用库的系统排程与重启接收器，不自写常驻服务。

## P4-A可靠性补充（2026-10-09）

已预排但尚在系统队列的通知，计划时刻之后最多保留24小时（边界不含）；这只是应用宽限策略，不是Android送达保证。必须同时具备本地实例、确定性系统ID、当前仍启用的来源及相同revision/发生时刻。年度跨年也适用。来源改动、任务完成/回收站、规则/总开关/待办开关关闭或权限撤销仍立即撤旧。没有对应排队实例的过去事项不补排；系统队列移除后不再补发，也不声称它已送达。宽限项与未来预排共用128条上限，先保留有效宽限项，再预排最早未来项；超时撤销，数据库仅记时间已过。

设置状态区分未来预排、宽限等待和单项失败。单项系统schedule失败记录error并继续其它项，显示可核对的失败标题；下次打开/手动核对只重试仍有效且未过期的失败项。读取队列/权限、取消旧通知或数据库提交失败属于整轮失败，不能报替换或核对成功。数据库故障不被当作普通单项排程错误吞掉。系统已排成但回执未写完，仍通过稳定ID及实际队列恢复，包含宽限期恢复。

本批不改库结构、不新增常驻服务或精确闹钟权限。测试在功能模块实现后集中执行；原生探针使用随机隔离库和专属通知ID，模拟时钟只证明真实队列核对行为，不替代锁屏/重启实际投递验收。
