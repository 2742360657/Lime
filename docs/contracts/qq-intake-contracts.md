# 正式QQ前台收件契约

日期：2026-10-11。基线fc0a762；本批复用已验证的官方QQ机器人HTTP、系统AES-GCM、WebSocket、前台生命周期及P3材料组件。真实扫码/短期Resume/TXT与PNG下载证据见[独立验证报告](../technical-baseline.md)，不据此承诺无缺口补收。

设置与助手共用QQ收件窗口：扫码、手动查询、解绑、显式约60秒前台读取、单件保存/重试、原件查看及明确选入聊天。绑定不触发读取；材料保存不触发模型分析。关闭窗口或进入后台停止网络操作；已有提交保留。二维码和绑定任务key仅短期内存，AppSecret与附件URL进入独立产品SecureStore命名空间 `lime-qq-product-v1`。不搬运 `lime-qq-validation` 沙箱凭据、消息或原件。

普通库新增local-only的 `qq_product_sessions`、`qq_product_messages` 和 `local_qq_items`。运行表保留session/seq及哈希账号、字符串消息ID、版本指纹；逐部件历史沿用材料关联字段。账号/消息/能力ID使用JSON元组哈希，避免原生NUL截断。本人C2C才登记，陌生人和群消息过滤后只推进已处理seq。

对于已确认本人和安全seq的消息，未知附件主机、无效附件描述、超限、不支持或SecureStore暂时失败先登记可见的逐件失败/未支持回执，再与消息及seq同事务提交。可读文字及其他有效附件保留，UI显示重新转发或直接导入指引。不会将媒体URL/响应/Secret或任意错误文本存进SQL。帧无法解析、seq不安全、SQL失败或取消时不推进对应seq；不能承诺平台一定重投，已知早期验证中拒绝附件没有获得重投。原件最多10MiB、文本最多32000字、单消息最多8份附件；超出文本明确标记只保留可显示前段，剩余内容需文件入口。

合法媒体能力先安全登记，再提交SQL引用；SQL失败时清理本次无引用能力。重复消息不重新登记已释放的能力；新版保留旧历史和原件、标记较早版本并释放被替代能力。下载与P3复制/解析独立重试，材料和部件回执使用hash及revision防重；取消或旧版本不得覆盖新回执。单件失败不阻断其他件保存。保存成功后释放对应媒体索引；下次显式读取按未保存的有效部件清理孤立索引，512项限制作用于待保存能力而非永久累计。

解绑仅清除此产品命名空间凭据/能力和运行会话，本机历史与材料保留；未保存媒体标记需要重新转发。Android原生模块销毁时取消自身WebSocket/HTTP、清理自身活跃临时文件、停止线程与连接池，避免Dev reload保留接收器；不扫描删除普通原件或其他模块文件。

根集成层负责将逐部件历史 `local_qq_items` 纳入完整备份的新版本，兼容v1/v2。运行会话、原始消息和全部渠道凭据/能力排除，`capability_id` 导出必须为null；未保存历史恢复为只读，已保存材料保持关联、冲突保留，不自动绑定/收件或授予模型权限。新一次本人鉴权收件可更新对应未保存恢复项，并以真实消息重新填写来源、文本、类型及文件名，避免把导入字段视为新鉴权内容。

本批先实现并集中验证受影响的本地事务、失败回执、重复、取消、单件重试、索引释放及备份/UI接入。真机统一放在全部本轮工作收尾后验收，期间没有ADB、模型调用或公开发布；原生销毁与产品扫码/手机UX不能仅凭Node测试记为通过。
