# 当前架构边界

产品依据：[产品定义](product-scope.md)。本文件约定后续实现责任，不宣称现有代码已全部符合。

```text
自然语言 / 微信与QQ转发 / 分享与文件
        ↓ 保存输入与原件，识别来源、去重
助手理解意图 + 查询相关本机历史 + 必要计算
        ↓ 受限业务命令、字段与版本校验
习惯 / 待办 / 备忘录及相关事实、来源、操作结果
        ↓ SQLite事务提交
可读的结果与来源 → 打开、更正、恢复
```

普通手动页面与AI操作共用业务规则。模型负责理解和生成参数，程序负责查询范围、校验、事务、可靠计算、去重与结果状态。个人事实、原始材料、聊天、活动和业务记录保持不同职责；泛化数据能力在内部支持广泛输入，不要求用户管理表结构。

基础存储继续使用现有PowerSync/OP-SQLite local-only模式，云模型直连沿用现有SDK。Key/平台凭据与普通记录分开。保留成熟备忘录、待办和习惯UI、文件原件、来源快照和操作回执；没有必要通过更换框架完成产品调整。

已用固定业务允许列表取代关键词口令，并支持按准确版本查询相关历史、保存本轮来源。程序应支持用户当前输入和相关历史的合理访问、普通明确操作的自主执行，以及高影响操作的具体预览。文档内容仍不能授予系统权限。

不维护旧格式转换或专用成绩模块。已清理日记入口和专用编辑器，复用备忘录共用逻辑与恢复能力；没有自动删除既存记录、原件或私密资料。

技术细节以[当前状态](project-status.md)和[现有契约快照](contracts/README.md)核查。新自主处理契约完成后更新对应文档，旧验收记录只保留其原版本含义。
