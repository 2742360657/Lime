# 日用记录依据与可恢复整理契约

日期：2026-10-11。本批实现复用既有活动、习惯、打卡、备忘录和待办；技术验收、真机交互与发布结果另记，不能从代码存在推断通过。

## 训练记录依据

`createDailyService(database, deps).readTrainingHistory({from, through, habitId?, kind?, limit?})`只读本机 `local_activities`、`habits`、`checkins`，日期按上海时间，范围最多366天。开始或结束在此范围内的活动各计一条，打卡按已保存的日期查询；可明确筛活动类型或已有习惯。未筛类型时是通用活动记录，不能将其全部表述为训练。

结果独立返回活动和打卡的 `matched / returned / complete / truncated`，默认各50条，最大各100条。活动状态 `active / completed / cancelled` 分别是计划中、已完成和已取消，状态总数由同一读事务内的精确计数得到。截断结果不能被表达为完整历史。关联打卡保留关联状态、习惯名和已存备注；关联活动与打卡不能相加充当训练次数。按类型筛选时，打卡仅包含关联该类型活动的记录；没有关联活动的独立打卡可按习惯查询。原有 `activity.complete` 保持一次打卡的事务回执，查询不产生新打卡。

此处不建立独立训练系统、不推断运动量、负荷或身体恢复，不给运动医学或医疗判断。助手建议只能引用用户实际保存的文字和有界记录；计划、取消、缺失关联及截断应明确呈现。查询不扫描日记或备忘录，不调用模型。

## 整理的授权范围

整理由用户手动选择最多20条具体记录及其版本。只支持 `memo.move`（移到已有备忘录分类或未分类）与 `task.trash`（软删除待办）。日记、习惯、打卡、原件和其它对象均不在批量修改范围，没有永久删除、自动全文分类、文件系统或SQL工具。

`previewOrganization(plan, {actor:'ui', batchId})`先持久保存预览；不改变业务记录。用户核对名称和动作后，`confirmOrganization(batchId, revision, {actor:'ui'})`才执行原子修改。关闭页面、重开应用均可从整理历史重新打开预览及回执；历史通过稳定日期/ID游标分页，较早批次仍可找到。目标分类须仍存在且类型为备忘录。

本机新增 `local_organization_batches`，所有字段属于local-only：`fingerprint, plan, before_snapshots, after_snapshots, receipt, status, revision, created_at, updated_at, undone_at`。状态为 `preview / applied / undone / restored`。独立批次回执不混入单实体 `local_operations`。相同ID与参数重试读取原批次；同ID不同参数拒绝。保存回执失败时，全部业务修改回滚。

快照严格白名单为 `id, entity, revision, groupId, sortOrder, deleted, title, hash`，不复制正文。预览仅对明确选中的记录计算完整字段摘要，不作文本分析；提交与撤销核对版本及摘要，连未增加版本号的后续内容变化也会阻止覆盖。备忘录移动保留原文，追加到目标分类排序；撤销恢复原分类和排序。待办仅改变软删除标记，撤销恢复可见。修改和撤销均递增版本，不回拨版本号。

`undoOrganization(batchId, revision, {actor:'ui'})`只处理已提交批次，先核对所有记录仍与批次提交后快照一致，再统一还原本批控制的字段。后续编辑、分类变化、缺失原分类或其它批次改动会阻止整批撤销；不覆盖新内容，不部分撤销。已撤销重试读取持久回执。

## 备份与入口

`validateOrganizationBatch`严格验证计划、前后快照转移和回执；`organizationDependencies`提供目标 `documents / tasks` 与新旧 `document_groups` 的历史引用。完整备份应纳入批次表并升级格式，兼容旧格式。恢复后的状态统一为 `restored`，保留审计内容，禁止确认、撤销或重放；历史引用可缺失，现存父对象冲突仍应阻隔该批次的导入。

`DailyToolsModal`供设置及助手紧凑菜单挂载一个“日用记录与整理”入口，内分训练依据与可恢复整理。既有紧凑日记、备忘录编辑器、原来的分类和待办页面继续复用，模型不直接取得整理写入权限。

## 集中验收案例

- 训练：日期边界、范围/数量上限、开始或结束日期、计划/完成/取消、关联与独立打卡、类型/习惯筛选、精确计数及截断说明。
- 整理：预览无修改、选择和白名单边界、批次幂等、正文及版本变化、事务末尾失败回滚、跨重开撤销、后续编辑冲突、原分类消失、恢复历史无执行能力。
- 备份：严格JSON、历史依赖、恢复惰性状态、v1/v2兼容与当前格式回环。
- 真机统一放在本批末尾：小米14选择/取消/预览/确认/重开/撤销、中文输入、记录刷新及独立预览包启动。未进行前不登记通过，不清应用数据。
