# P5-04 完整本机备份与安全恢复验收

日期：2026-10-10。分支 `feat/p5-local-backup`，当前实现 `f045420`。本批仅手机业务数据的手动 ZIP 导出恢复；没有服务器、云存储、自动分析或新增账号。实现、技术验收、人工日用与发布状态分别记录。

设置中的“数据备份”现在导出完整业务 ZIP，“数据恢复”支持它和既有基础 JSON。范围包括记录、草稿、人格原文、显式记忆、活动/打卡、聊天、来源/建议/操作回执、材料原件/分析图片及提醒规则。采用 Android 系统 `java.util.zip`，没有新增 npm 依赖或自写压缩算法。明确格式/容量及平台依据见[备份契约](../../contracts/backup-contracts.md)。

不导出 API Key、渠道凭据、Agent grants、系统通知实例、迁移内部标志、外观/头像、未处理分享队列或微信独立验证沙箱。ZIP 是明文私密文件；保存它不触发模型或上传。它是完整业务记录包，不是手机系统镜像。

同 ID 同内容跳过；不同内容及依赖冲突的对象不覆盖，整个输入包保存为可再次导出的恢复副本，其余独立对象新增。恢复历史请求/未接受建议不可执行或重试，已有操作回执用于回看。新增人格、提醒规则停用；新增待办当前版本抑制到期排程，显式编辑后才按现有设置排程。现有设置不覆盖，也不从包恢复工具权限。

修正后类型检查和受影响备份 suite / 12 项通过；当前共定义 98 项，没有声称重新运行完整 98 项。其余 84 项沿用本批 `d8b0522` 检查范围。只重跑受影响原生探针，没有重复云调用、提醒权限申请或旧功能全套。

## 小米原生技术验收

小米14 / Android16，通过 USB 覆盖安装，未卸载或清数据。debug APK 原生基线 `d8b0522`，探针 JS 由本仓库 Metro 提供 `f045420`。两个随机隔离 local-only SQLite 库和合成原件执行：

- 日记原文/未提交草稿、习惯/活动完成打卡、显式记忆、人格、聊天请求/消息、待办建议/回执与来源、提醒规则、文本/图片/扫描 PDF 回环。
- 实际系统 ZIP 打包/解包、blob hash/大小、原件及分析图片跨目录改写；重复导入不新增。
- 当前内容冲突不覆盖、独立对象新增、整个冲突 ZIP 保留；包含恢复副本的下一份备份再回环。
- 末尾导入回执故障时 SQL 全回滚，再次执行成功；恢复请求/建议不能执行，授权未恢复，规则/人格停用。
- 原生拒绝路径穿越、未知条目、hash 不符及过大清单；关闭重开记录/恢复副本仍在，上传队列 0。

结果 `status=passed`，模型调用 0。探针只清理自己创建的随机库、缓存阶段和明确登记的新合成文件。debug 期间普通记录 14 类行数/摘要前后一致；这不是所有文件逐字节或 preview 安装后的 SQL 全量比较。

## 人工与发布限制

最终 `f045420` preview 已覆盖安装，手机 APK SHA256 与上表一致。停止本任务 Metro、移除 8081 映射后独立启动通过；设置范围文案、系统选择取消、合成空 ZIP 的 content URI 读取/范围确认/取消及强停重开通过，没有导出或导入真人记录。小米自有选择器返回行为与脚本预期不同，改用其显式取消和文件确认按钮后完成该段检查，未修改产品代码或重跑旧套件。合成下载文件已清理。

完整系统目录保存、恢复副本导出、真实旧 JSON 提供方读取和人工日用体验仍待验；原生 ZIP/SQLite 探针不替代全部系统提供方和 UI 验收。

文件采用不可变副本先安装、SQL 随后一次事务提交。SQL 失败可能留下不被业务引用的私有文件；当前没有自动物理清理。相同记录已存在但原件丢失/损坏时，本轮不承诺自动修复旧原件引用。冲突副本随下次包一起保存，达到 256MiB 上限时明确失败，不静默删历史。

原生重复 ZIP 条目有拒绝逻辑，但未构造实际重复条目的手机夹具；容量上限极端包、空间耗尽、复制中强杀、所有 UTF-8/压缩格式组合、系统提供方中途卡住或撤权未实测。未以本批通过补填手机真实云聊天、中文输入、人格表达、实际通知送达、微信正式收件或 QQ。

下一模块仍按[当前路线](../planning/next-development-review.md)集成已验证的微信正式前台收件，复用 P3 原件/明确选择/聊天流程；普通接收不自动送模型。集中人工数据导出恢复与真实日用流程继续单列，不引入后台服务器或重设计日记。
