# 开发方案与阶段门槛

**历史参考，已由[修订版开发计划](development-plan-revised-before-reset.md)替代。** 以下保留原版范围供对照，不再作为当前实施入口。修订版明确未配对启动条件、local-only必要改造、P2新增模块工作量及独立验证线。

日期：2026-10-09。当前只交付P0，供用户二度评估；不提前实现后续功能。范围以手机独立版为准，服务器能力不进入路线。

## 主线和不变规则

先稳定本地记录，再让前台助手能真实操作同一份数据，然后统一材料与渠道，最后完成提醒/个人场景及发布。基础日记保持简洁，已有页面尽量复用。人格/个人记忆与业务、材料分开；常规保存不自动分析。

每阶段交付可使用的完整流程，不以建表或生成聊天文字当完成。版本、来源授权、原文、幂等和失败恢复跟随能力实现；不最后才补。阶段中做小Git提交，功能完成后集中测试。

## 阶段定义

| 阶段 | 范围 | 完成门槛 |
|---|---|---|
| P0 当前 | 独立源码仓库、品牌/身份、来源、评估、选型、流程、测试台账、公开发布 | 仓库可访问、公开内容检查通过、状态真实；不称独立APK已完成 |
| P1 本地记录与服务器退出 | 本地DB provider/local-only schema；移除连接器、旧凭据初始化、配对/同步菜单和文案；复用记录/导出合并；新身份/签名工程验收 | 不需要服务器/票据/私网就能启动→日记/备忘录/任务/习惯本地写入→返回/重启→读回→导出/合并。没有上传队列增长，不清旧数据；旧应用与新应用并存 |
| P2 前台助手 | Key与模型设置、显式provider/Agent、角色私密导入、明确事实/偏好、会话/活动/提议/回执、共用任务/习惯命令、流式/停止、操作结果 | 无服务器，聊天→查建改待办/习惯→普通页面一致→换会话承接训练完成一次打卡→重启状态保留。恶意材料/旧版本/重复命令不突破边界 |
| P3 材料与上下文 | 直接文件/图片、系统分享/打开、统一原件/来源、文本与图片/有限PDF、本地引用快照/建议接受、来源回看、记忆查看/更正/忘记 | 分享/打开→保存→聊天分析→编辑建议→接受→打开待办及原文，离线记录不受影响；临时URI/重复/取消失败有出口，支持格式如实列明 |
| P4 渠道显式收件与本地提醒 | 微信ClawBot优先、QQ官方机器人随后；本人绑定、手动连接收取、下载/游标/回执；生日/到期规则及本地通知 | 应用关闭时转发→打开点读取→原件本地保存→助手处理；离线补收范围有实际结果。提醒更正撤旧/取消，Xiaomi锁屏/重启/权限及跳转实测；不需要全天接收服务 |
| P5 日常使用与发布 | 精确成绩查询/训练历史、授权分类归档/撤销按真实需求增量；整体精简交互/中文IME、恢复范围、依赖风险、正式签名包与失败出口 | 选定个人场景端到端成立，技术和人工体验分别记录。正式包独立运行，发布说明明确已交付与限制；不靠扩大功能清单延迟可日用版本 |

P1和P2完成后已有可日常试用的本地记录+助手主线，不等待微信/QQ或全格式文档才体验。P3/P4失败项不能用隐藏服务器弥补后写通过；保留直接文件路径并说明范围。

## 每阶段实施顺序

1. 从当前状态选择本阶段，列出待退出旧调用和本阶段台账条目；先给出对象/命令/副作用边界。
2. 复用库与现有UI，在适配层逐消费者切换。普通页面和助手命令统一，不两套独立数据。
3. 完成错误/取消/重启/版本/重复回执流程，再进入下一能力；开发中只简要登记待测项。
4. 阶段功能完成后统一检查/构建/自动化/真机；失败只修相关路径并复测；写验收报告和状态。
5. 用户反馈/新问题影响范围时更新当前方案，不把过期“下一步”继续当开发入口。

## 本轮之后的第一批具体工作

- 建立本地数据库provider，明确local-only新schema与旧基础记录导入；保留现有记录格式ID与分类关联。
- 清点AssistantProvider消费者，先替换普通记录启动、状态、设置及恢复文案；旧HTTP助手明确尚不可用，P2再接直连。
- 消除任何“应用启动必须配对服务器”或隐式连接路径；整理记录结果语义为本机提交。
- 集中验收新包身份、纯本地启动/重启和基础记录，再进入P2。禁止删除旧应用或清SQLite作为捷径。

## 暂缓与非目标

自建服务器/同步/管理员后台、账号注册/社交、“过客”、24小时手机自主Agent、自动读所有群聊、完整向量平台、富文本编辑器重写、农历与全格式文档、复杂多人协作，均不阻断首版。

独立备份/云存储用户已暂缓，不索取目标或默认部署；基础手动导出/恢复继续保留。后续是否扩全量本地导出由实际新增对象决定，Key/平台Token始终排除。

## 估算与决策点

不先承诺固定日期。P1工作量取决于旧表迁移/消费者退出；P2取决于Hermes/SDK实际兼容；P4取决于平台账号与离线补收。阶段结束用完成结果修订后续范围。遇到确需用户选择的账号、材料策略、权限或无法复用的重大组件，及时给具体问题和替代方案；不每小改动重复询问。
