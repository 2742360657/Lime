# P1本地存储迁移

日期：2026-10-09。此处说明实现路径；通过/未测结果另见阶段报告。

## 文件和职责

- `lime-local.sqlite`：本应用的新主库，所有表local-only；复用PowerSync事务/订阅和OP-SQLite，不创建connector。
- `angelime-assistant.sqlite`：仅在同包沙箱确实存在时作为旧数据来源；按旧schema打开，绝不翻旧业务表的localOnly标志、不connect、不清队列、不删除旧文件。
- `habit-checkin/data.json`：历史导入及普通设置/本地记录副本。业务记录读写依据SQLite；已有导入标志随DB迁移，陈旧JSON不会重新覆盖数据库记录。
- 旧应用包：与Lime隔离，必须在旧应用导出基础记录，再在Lime合并导入；不能借跨包迁移卸载或清数据。

旧库打开会运行SDK自身初始化/维护，不能声称文件字节完全不变；代码不向旧库写入用户记录。旧库/WAL留在应用内，作为失败恢复来源。

## 原子搬运

DB provider在任何业务页面挂载前初始化新库。若完成回执`lime-local-migration-v1`已存在，不再导入旧库。没有旧文件时仅原子记录新安装状态，然后初始化本地instance ID。

存在旧文件时，以旧库只读事务提供稳定快照，在新库的一次写事务中搬运全部10张应用表。每批200条，按ID分页；字段来自固定schema，不从材料或模型生成SQL。保留ID、版本、关联、回收站、草稿、失败副本、建议和本地聊天缓存；不搬运内部同步表/上传队列或SecureStore凭据。

逐条读回并对照全部字段，每张表核对来源数量，最后在同一事务内写完成回执。新库有未确认内容而缺少回执时拒绝覆盖；出现异常则新库事务回滚。进程中断后重试，旧文件保留。回执存在后继续编辑新库也不会再导入旧快照。

`DatabaseProvider`未就绪时不挂载记录页面，失败只给重试，不提供空白可写数据集。不读取旧服务器Key、不等待网络，重试复用单次初始化Promise以避免并发搬运。

基础JSON导入继续沿用已有business/memo独立标志及恢复语义；复制这些标志保证升级后不会重新复活旧JSON记录。缺少标志的历史JSON只受控导入，冲突保留副本，不覆盖较新内容。

## 验证边界

Node真实SQLite测试验证搬运、失败回滚/重试、分页、较新记录保留和导出/恢复逻辑；不能据此声称PowerSync原生队列正确。开发菜单原生探针使用独立合成库验证真实同步表队列→迁移→local-only写入→关闭/重开后的状态与队列。

模拟器阶段验收另验证实际应用无服务器启动、记录UI、导入恢复及进程重启。真机中文IME/交互体验单独列待测，不借旧包证据填通过。
