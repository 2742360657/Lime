# 交互与信息组织

本文约定现有功能的呈现与操作方式。业务保持离线，无账号、同步或后台服务；更新检查单独管理，不改变打卡规则。

## 页面职责

- 今日是行动概览：先展示逾期和今天截止的待办，再展示所有可记录的习惯，最后展示其他日期及无日期的待办。未来的截止日期不等于开始日期，任务可以提前推进。所有未完成任务都可找到，不截断无日期条目。
- 待办是完整的任务浏览与管理页面：展示标题、备注摘要、截止日期，日期筛选直接可见；点内容编辑，点日期改期，点条目菜单查看更多操作。已完成任务保留原有查看和恢复入口。
- 习惯与备忘录使用相同的分类筛选、整理入口和条目操作语言。设置承载个人资料、六套主题、归档及本地备份恢复。
- 顶部固定页面名称、“新建”和“整理”等常用操作，底部保留五个主入口；新建不再悬浮遮挡任务或打卡按钮。页面抽屉只从屏幕左边缘打开，减少与内容操作的手势竞争。

## 日期、分组与排序

待办的分组由截止日期和时间自动计算，不是额外的手工分类：逾期、今天、明天、未来 2–7 天、7 天以后、无日期。同日已超过具体截止时间的任务归入逾期；未设具体时间的任务当天不会因时间被判为逾期。

默认按截止日期、具体时间排序，相同截止时间以及无日期任务内按手动顺序排列。排序界面明确说明这个优先级；试图用拖动打乱不同截止时间的先后时会解释原因。跨日期分组拖动必须确认改期，也可以选择只排序、保留原日期。

改期操作显示实际日期：今天、明天、3 天后、30 天后、无截止日期。原有具体时间保持不变；清除日期后具体时间不参与分组。原先“未来 7 天／稍后”对应的 3 天／30 天规则没有改变，只消除了操作文案与实际结果的不一致。

日期分组在页面可见时每分钟刷新，应用返回前台时立即刷新，不运行后台计时服务。

## 紧凑视觉

采用紧凑的现代Android形态：动作和筛选为胶囊，输入/小控件12dp、内容卡片16dp、对话框/底部面板24dp圆角。主列表通过背景与表面区分层次，减少重复轮廓边框，减轻常规文字的字重；保留六套主题和可读字号，通过点击区域或hitSlop保持小型控件可操作，大字号允许换行。

## 整理与编辑

- 顶部“整理”是直接入口，长按和条目菜单仍可进入并预选该条目。
- 整理页面区分“多选”和“排序”：多选时整行切换选择，显示已选数量、全选与底部批量动作；排序时只展示拖动把手，松手即保存。批量移动后清空选择，避免再次操作已离开当前筛选范围的任务。
- 习惯分组管理提供可见的排序按钮，原长按入口保留。
- 待办和习惯编辑统一取消、保存和键盘避让，空名称不可提交；有未保存修改时，取消或系统返回会确认放弃。
- 备忘录打开后即可浏览，点正文原位编辑、长按选字；正文保持单一有界原生滚动面，松手后使用系统惯性续滚，触碰制动。标题与分类收紧，不增加阅读/编辑切换按钮。选区拖动、长按和多指操作交给原生编辑器；文字、视口或生命周期改变时停止惯性。
- 备忘录保留 600ms 自动保存、手动保存、返回前保存或放弃的原有语义；保持键盘打开时正文末尾可滚动。编辑回调保持稳定，避免自动保存反复触发无内容变化的写入。
- 浏览和多选使用虚拟列表，日期/分类标题与条目平铺；备忘录搜索固定在筛选条下方，不随列表滚走。排序模式保留专用拖拽视图。
- 保存状态区分编辑中、保存中、已保存和失败；备忘录手动保存成功后才关闭，失败保留内容并可重试；切后台提交尚在防抖窗口中的草稿。
- 完成与打卡仍可撤销；直接删除待办、永久删除备忘录和清空回收站需要确认。普通备忘录删除仍先进入回收站。

## 验证

`npm run check` 包含日期分组边界、全部未完成任务覆盖、排序优先级、具体改期日期及六主题文字对比度回归。布局、键盘、长标题、选择/拖动、保存重开与大字号，以及正文真实松手续滚/触碰制动/反向和选区保护必须另外在隔离 Android 环境验证；类型检查不替代实际界面操作。
