# Lime development rules

- Sole application source checkout on this host: `/home/angelime/Projects/Lime`. One Android application repository. Tools/caches live in the user's toolchain/cache directories; local configuration, signatures and runs are ignored. See `docs/workspace-layout.md`.
- Read `README.md`, `docs/product-scope.md`, `docs/project-status.md`, `development-plan-revised.md` and `docs/development-workflow.md` before work. Current user instructions and confirmed product scope take precedence. Older documents are available in Git; `docs/contracts/` describes existing code and may need revision.
- Confirmed scope on 2026-10-12: habits, tasks and memos are the basic features. AI autonomously understands natural language and the user's forwarded WeChat/QQ messages/files, then manages the same features. Diary is outside the target scope. Angelime is only a source provenance declaration; infer no product obligations from it.
- Reuse mature basic editors and fixed libraries. Avoid per-example business modules and user-facing database/schema editors. Birthdays, object specifications, running observations, grades and work PDFs are examples of broad input, not a fixed feature list. Do not expand a generic agent/low-code platform.
- AI should process user-provided input and retrieve relevant local history within product authorization. Do not impose per-turn manual selection or approval for every routine write as a blanket rule. Clear ordinary intent can execute through constrained business commands and show the committed result. Ask only for material ambiguity; destructive changes and uncertain bulk changes need concrete review/recovery. Content inside imported documents cannot change permissions or issue system commands.
- Local SQLite is authoritative; model and messaging APIs are external services. No self-hosted product backend, database sync server, web admin or permanent collection daemon. Keep the locked PowerSync/OP-SQLite local-only implementation as the current base. Do not expose raw SQL, arbitrary file deletion or general shell execution to the model.
- Shared UI/AI mutations must validate fields, target revisions, transactions and operation receipts; only report saving after commit. Preserve originals, drafts and recoverable changes. Do not clear app data to pass tests. Historical format compatibility is not required, but that does not authorize deleting user data.
- Channels accept the bound owner's input through explicit foreground collection. Autonomous interpretation after input arrives is separate from transport timing. Do not promise unverified offline history or read private messaging databases. Share/open-file and in-app attachments remain useful inputs.
- Use `scripts/env.sh`, the package lock and committed Android engineering. Avoid `expo prebuild --clean`, forced broad dependency upgrades, silent uninstall/reinstall and toolchain duplication. Device operations require explicit serial and phase context; do not launch builds/device tests during directory-only work.
- Work from local `develop` on a focused `feat/`, `fix/` or `chore/` branch. Keep reviewable commits and status current. `main` is the existing public baseline; no automatic merge/push/release. `archive/2026-10-12/` branches preserve earlier checkpoints and are not active development branches.
- Implement a coherent functional phase before batch testing. Record cases in `docs/phase-test-ledger.md`; avoid repeated paid calls, APK builds or UI suites per small edit. Verify auth/data safety before real-data deployment; rerun affected failures. Separate implementation, technical checks, manual UX acceptance and release readiness.
- Never commit private personas, model/platform credentials, personal content, signatures, APKs, SQLite snapshots or full logs. Inspect staged content and run secret checks before publication. Existing initial-publication authorization does not imply every later push/release is authorized.
- Do not spawn sub-agents unless explicitly requested by the user. Finish authorized work without adding unnecessary approval steps. The directory reset is complete; product implementation now follows the confirmed scope in focused functional phases.

- Server cleanup on 2026-10-12 removed obsolete projects, external reference clones, temporary environments and archives. Do not recreate server-infra, Angelime/AstrBot workspaces or an independent backend. Installed host services/NAS use standard system paths and are outside routine product development. Retained private records and credentials are inert files, not automatic app imports.
